# 第二輪:首頁頁籤反查

第一輪把「嘉女沒有細分類頁」寫成結論,那是錯的。首頁頁籤的內容是 JavaScript
動態載入的,靜態 HTML 裡看不到任何公告,但頁籤區塊裡有這行:

```
$.hajaxOpenUrl('/app/index.php?Action=mobileloadmod&Type=mobile_rcg_mstr&Nbr=401', ...)
```

**`Nbr` 就是分類 ID**(以「校園訊息 Nbr=12」對照已知的 403-1008-12 驗證無誤)。
反查後嘉中補到考試訊息(401)、升學資訊(386)、防疫專區(430);
嘉女補到研習活動(548)、競賽與投稿(679)、資訊安全(742)、獎助學金(547)、考試訊息(11)。

都沒有自有公告**,段考範圍不由實驗研究組在網站上發布。

# 第三輪:全站地圖(site_map 模式)

## 為什麼前兩輪還是不夠

實際漏抓案例:`/p/406-1008-136178,r168.php`(115學年度高一新生住宿相關資訊,8/10 發佈)
沒被抓到。從 `,r168` 反查得知它屬於 **403-1008-168「新生專區」**(20 筆:校服、住宿、
新生健檢、資優班錄取、成班名單)。這一頁**既不在網站導覽、也不在首頁頁籤**,
前兩輪的方法無論如何都找不到它。

結論:只有「爬遍全站 + 把分類 ID 從 1 掃到底」才能宣稱窮盡。

## 方法(`python scraper/discover.py site_map`)

1. **BFS 爬站**:從首頁與網站導覽出發,只走站內 `*.cy.edu.tw` 的 412 頁面,
   單校上限 400 頁、間隔 1 秒;沿路收集所有 403 連結與每頁 script 裡的 `Nbr`。
2. **地毯式補掃**:把 BFS 沒覆蓋到的分類 ID 全部掃過。
3. **覆蓋分析**:抓遍所有非空分類頁,取得各頁的文章集合,用貪婪集合覆蓋
   選出「能帶來獨特文章」的最小頁面集合。

## 掃描上限踩到的坑

一開始把上限設在 850,但嘉中「藝文活動」在 **908**、嘉女「圖書館公告」在 **1177**,
兩個都超出範圍,只是碰巧被 BFS 的連結撈到。補掃到 1500 之後,嘉中又多出
**52 個**有內容的分類(最新消息 21 筆、成果發表 16 筆、旭陵圓夢計畫 11 筆、
小論文、閱讀心得、班級模範生、新生訓練、畢業典禮……)。
`MAX_CATEGORY_ID` 已改為 1500,這件事本身就說明「猜區間」不可靠。

## 412 處室頁全部移除

文章網址的 `,rXXX` 就是它的 403 分類 ID,所以**收齊有文章的 403 分類,
數學上就涵蓋了所有文章**;412 處室頁只是同一批文章的另一個入口。
上一版 config 裡的 8 個 412 頁因此全部改為對應的 403 分類頁
(例如 412-1008-151 行事曆 → 403-1008-246 行事曆)。
