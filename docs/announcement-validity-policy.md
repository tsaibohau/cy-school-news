# 問校務公告時效與效力判斷

狀態：feature 實作規格，尚未部署正式站  
判斷基準日：執行當下的臺北日期；測試固定使用 `2026-08-30`

## 目的

問校務在整理答案以前，先判斷每則公告或片段的效力。這個功能只控制回答時的引用方式，不刪除公告、不改寫爬蟲產生的公告 JSON，也不以公告發布年齡直接判定過期。

## 回答政策

| 狀態 | 問校務處理 |
| --- | --- |
| 目前有效、期限內 | 可引用，仍保留官方來源 |
| 尚未生效／事件未開始 | 可說明未來安排，不冒充目前已生效 |
| 本次已過期 | 現況問題中排除；若只找到過期資料，明說期限已過 |
| 部分有效 | 排除舊日期、舊金額與舊驗證資訊，只引用仍可辨識的程序並警告 |
| 效力未確認 | 可提供官方入口或暫時依據，但必須顯示未確認原因 |

## 保守規則

- 法規、要點、準則、管理規定不因發布多年而自動失效。
- 上一學年度的名單、申請、活動或課程安排不能證明本學年度現況；學年度字樣不會自動廢止法規。
- 有明確截止日的報名、申請、繳費、活動或施工，依截止日或事件日判斷。
- 「另行通知」而找不到恢復公告、附件不可讀、正文亂碼或日期缺失時，不自動宣稱有效或失效。
- 混合型公告必須按片段判斷；舊學期的日期與金額不得被帶入目前回答。
- 新舊法規只有在有明確取代證據時才能建立取代關係；否則並列日期並標示效力未確認。
- 未來可由爬蟲寫入結構化 `validity` 標註；人工或高可信標註優先於推論規則。

## 片段級資料模型

每則公告可含多個 `fragments`，各自保存生效日、結束日、狀態與回答政策；`until_superseded` 表示跨學年度沿用至官方修正。`relations` 表達部分更正、期限延長與局部取代，日期較新或主題相同不足以推定整份取代。

人工審核紀錄保存在 `announcement-validity-reviewed.js`，不寫回爬蟲產生的 JSON。沒有人工紀錄時才使用保守推論。

## 整合範圍

- `announcement-validity-reviewed.js`：人工確認的真實公告片段與文件關係。
- `announcement-validity.js`：分類、片段效力、文件關係與引用政策。
- `assistant-qa.js`：依問題選取並組合可用片段。
- `app.js`：在參考公告顯示效力標籤與資料限制。
- PWA 與 staging builder：確保新模組與問校務使用同一版殼層。

刪除公告功能不在本次範圍。只有在人工判定規格、真實公告測試與持續監測都足夠後，才可另行設計可復原的封存或刪除流程。
