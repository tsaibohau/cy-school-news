# 個人資料保存與刪除規格

版本：Preview 草案，2026-08-30。正式啟用前仍需法律審查。

## 資料最小化

| 資料 | 用途 | 保存原則 |
|---|---|---|
| Supabase Auth 登入識別 | 建立個人資料命名空間 | 使用帳號功能期間；完整刪除需私密身分核對流程 |
| 偏好／個人化設定 | 排序與介面設定 | 直到使用者自行清除或帳號刪除 |
| 關鍵字追蹤 | 公告提醒 | 直到使用者刪除；已軟刪除列應在 30 天後清除 |
| 閱讀紀錄 | 未讀狀態 | 最長 365 天或使用者自行清除，以較早者為準 |
| 待辦 | 個人待辦與提醒 | 直到使用者刪除；已軟刪除列應在 30 天後清除 |
| 推播裝置資料 | 對指定裝置送出提醒 | 停用裝置時立即解除；失效端點不得繼續使用 |

## 使用者可自行做的事

Preview 帳號卡新增「刪除已同步資料」。完成確認後，系統依目前已部署 schema 刪除該登入者的偏好、關鍵字追蹤、閱讀紀錄與待辦，清除該帳號的本機同步狀態並登出。它不會刪除 Google 帳號，也不會自動刪除 Supabase Auth 中的登入識別。

## 尚未完成的強制控制

- 30 天軟刪除清除與 365 天閱讀紀錄上限尚未有已部署排程；在排程與驗證完成前，以上期限是目標規格而不是已執行承諾。
- Supabase Auth 登入識別的刪除需要伺服器端管理權限與私密身分核對流程，不能交給公開 Issue。
- 私密更正、停止利用與申訴管道尚未指定負責人；這仍是正式發布阻擋項目。
