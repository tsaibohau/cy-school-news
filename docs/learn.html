1全貌：資料怎麼從學校跑到你的手機

整個網站其實只有一條資料流：

  1. GitHub Actions 定時叫醒一台雲端電腦。
  2. 電腦執行 Python 爬蟲，讀學校官網的公告列表。
  3. 爬蟲把結果整理成 JSON 檔（一種純文字的資料格式）。
  4. JSON 檔存回 GitHub，GitHub Pages 把 docs/ 資料夾變成網站。
  5. 你的瀏覽器下載網頁和 JSON，用 JavaScript 排好顯示出來。

這種做法叫「靜態網站」：沒有自己的伺服器要顧，費用是 0 元。需要登入、存個人資料的部分才交給雲端資料庫 Supabase。

2準備工具

  • GitHub 帳號：放程式碼、跑自動排程、架網站，都免費。
  • VS Code：寫程式的編輯器。
  • Python 3：寫爬蟲用。安裝後在終端機輸入 python --version 確認。
  • Git：記錄每一次修改，可以隨時回到以前的版本。
# 下載這個專案到自己電腦
git clone https://github.com/tsaibohau/cy-school-news.git
cd cy-school-news
pip install -r scraper/requirements.txt

小技巧：每做一個新功能就開一個「分支」（branch），做好再合併回 main。這樣正式網站不會被做到一半的東西弄壞。

3網頁骨架：HTML、CSS、JavaScript

網頁由三種檔案組成：HTML 是內容和結構、CSS 是外觀、JavaScript 讓它會動。最小的公告頁長這樣：

<!doctype html>
<html lang="zh-Hant-TW">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>我的校訊</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>最新公告</h1>
  <ul id="list"></ul>
  <script src="app.js"></script>
</body>
</html>

本站的 docs/index.html 就是放大版：上面是標題、中間是各個分頁（公告、行事曆、課表、問校務），下面是導覽列。按導覽列時，JavaScript 只是把某一區顯示、其他區藏起來，不用重新載入頁面。

上線：在 GitHub 倉庫的 Settings → Pages，選擇從 main 分支的 /docs 發布，幾分鐘後就有網址。

4爬蟲：用 Python 讀公告列表

爬蟲做的事跟你自己打開官網一樣：下載網頁、找到公告的標題、日期和連結。用 requests 下載、BeautifulSoup 解析：

import time
import requests
from bs4 import BeautifulSoup

URL = "https://example.edu.tw/news"   # 換成你要讀的公告列表網址

def fetch_list(url):
    html = requests.get(url, timeout=20,
                        headers={"User-Agent": "my-school-news (教學範例)"}).text
    soup = BeautifulSoup(html, "html.parser")
    items = []
    for row in soup.select("table tr"):        # 每一列是一則公告
        link = row.find("a")
        if not link:
            continue
        items.append({
            "title": link.get_text(strip=True),
            "url": requests.compat.urljoin(url, link["href"]),
        })
    return items

items = fetch_list(URL)
time.sleep(1.5)   # 每次請求之間至少等 1.5 秒，不要拖慢學校的網站
print(items[:5])

每間學校的網站長得不一樣，所以本站的 scraper/scrape.py 為不同的網站系統寫了不同的「轉接器」（scraper/adapters/），再把結果統一成同一種格式。

為什麼要等 1.5 秒？

學校的伺服器通常不大。一秒內連續送幾十個請求，可能讓其他同學打不開網站。慢慢讀、只讀需要的頁面，是寫爬蟲最基本的禮貌。

5資料檔：把結果存成 JSON，網頁再讀出來

Python 把清單存成 JSON：

import json
with open("docs/data/announcements.json", "w", encoding="utf-8") as f:
    json.dump({"items": items}, f, ensure_ascii=False, indent=1)

網頁用 fetch 讀回來，一筆一筆放進清單：

fetch("data/announcements.json")
  .then((res) => res.json())
  .then((data) => {
    const list = document.getElementById("list");
    data.items.forEach((item) => {
      const li = document.createElement("li");
      const a = document.createElement("a");
      a.href = item.url;
      a.textContent = item.title;   // 用 textContent，不要用 innerHTML，避免被插入惡意程式
      li.appendChild(a);
      list.appendChild(li);
    });
  });

試試看：下面是用假資料做的小搜尋框，跟本站公告頁的搜尋是同一個概念——把每一則的標題拿來比對你打的字。

    6自動排程：GitHub Actions

    不想每天自己按「執行」，就讓 GitHub 幫你定時跑。在 .github/workflows/ 放一個 YAML 檔：

    name: scrape
on:
  schedule:
    - cron: "17 * * * *"     # 每小時第 17 分跑一次（時間是 UTC）
  workflow_dispatch:          # 也可以手動按按鈕執行
permissions:
  contents: write
jobs:
  scrape:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r scraper/requirements.txt
      - run: python scraper/scrape.py
      - name: 有新資料才存回去
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add docs/data
          git diff --cached --quiet || git commit -m "更新公告"
          git push

    本站的 scrape-hourly.yml 多做了幾件事：抓公告內文、整理行事曆和課表、送通知、產生縮小版的首頁資料，讓網頁開得更快。

    排程不要設太密。本站固定低頻率抓取，對學校伺服器比較友善。

    7離線 App：PWA

    PWA 讓網頁可以「加到主畫面」，像 App 一樣打開，沒網路也看得到上次的內容。需要兩個檔：

    manifest.webmanifest：App 的名字、圖示、顏色。

    {
  "name": "我的校訊",
  "start_url": "./",
  "display": "standalone",
  "icons": [{ "src": "icons/icon-192.png", "sizes": "192x192", "type": "image/png" }]
}

    sw.js（Service Worker）：在背景把網頁檔案存在手機裡。

    const CACHE = "my-news-v1";
self.addEventListener("install", (e) => {
  e.waitUntil(caches.open(CACHE).then((c) => c.addAll(["./", "./index.html", "./app.js"])));
});
self.addEventListener("fetch", (e) => {
  e.respondWith(caches.match(e.request).then((hit) => hit || fetch(e.request)));
});
    為什麼本站的檔名後面有 ?v=147？

    手機會把檔案存起來重複使用。改了程式卻沒改版本號，使用者可能一直看到舊版。每次修改就把版本號加一，瀏覽器就知道要下載新的。

    8問校務：不用 AI 也能做的問答

    問校務是「規則式」的：沒有呼叫 AI，而是把問題拆成關鍵字，再到公告和學校規章裡找最相關的段落。主要步驟：

    1. 整理問題：去掉「請問」「嗎」這類不影響意思的字。
    2. 同義詞：「段考」也找「期中考」（qa-synonyms.js）。
    3. 錯字：打成「段烤」也認得（qa-typo.js）。
    4. 判斷意圖：問「怎麼辦」要回答步驟；問「會怎樣」才回答後果。
    5. 打分數：標題、內文命中關鍵字的次數和位置決定排名，最高分的拿來組答案（answer-composer.js）。
    function score(question, doc) {
  let s = 0;
  for (const word of question.keywords) {
    if (doc.title.includes(word)) s += 3;   // 標題命中比較重要
    if (doc.text.includes(word)) s += 1;
  }
  return s;
}

    好處是快、免費、每個答案都找得到出處；缺點是要一直補規則。本站每次改版都會拿一批真實問法去問，答錯的就補規則，再寫成自動測試（tests/）防止以後退步。

    9帳號與資料庫：Supabase

    收藏、待辦、提醒這些「每個人不一樣」的資料，不能放在公開的 JSON。本站用 Supabase：它提供登入（Google 帳號）和 PostgreSQL 資料庫。

    最重要的觀念是 RLS（資料列層級安全）：在資料庫裡直接規定「每個人只能讀寫自己的資料」，就算有人改了網頁程式也繞不過去。

    alter table public.tasks enable row level security;

create policy "只能看自己的待辦"
  on public.tasks for select
  to authenticated
  using (user_id = (select auth.uid()));

    資料庫的每一次結構變更都寫成一個檔案放在 supabase/migrations/，誰改了什麼、什麼時候改的都查得到。

    本站也用同樣的方法把資料分成公開和限制兩種：公開的放在網站上；不能公開的存在私有儲存空間，只有通過驗證的管理員讀得到。

    金鑰、密碼、Token 一律存在 GitHub Secrets 或 Supabase 的設定裡，絕對不要寫進程式碼。公開倉庫裡的東西，任何人都看得到，而且刪掉以後歷史紀錄裡還在。

    10守則與下一步

    • 尊重來源：只讀公開、不需登入的頁面；顯示標題、日期和官方連結，需要完整內容時請讀者回官網。
    • 保護個資：名單、成績、聯絡方式不要轉存或做成可以搜尋的資料。
    • 先測試再上線：改了爬蟲就跑 python tests/test_parser.py，全部通過才合併。
    • 留下紀錄：每次修改寫清楚做了什麼、為什麼（本站記在 PROJECT_LEDGER.md）。
