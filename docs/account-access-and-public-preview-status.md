# 帳號審核與公開公告最小檢視：進度紀錄

更新日期：2026-09-03  
適用分支：`codex/username-password-login`  
環境：Supabase staging 與 Vercel Preview；未合併 `main`，未部署正式站。

## 已完成

- 嘉校快訊帳號使用「使用者名稱 + Email + 密碼」註冊；密碼由 Supabase Auth 保存與驗證，網站不保存密碼。
- 註冊與 Email 驗證後，帳號預設為 `pending`。只有管理員核准為 `approved` 後，才能同步與使用問校務、個人通知、待辦與個人行事曆。
- 管理員可在網站的「帳號審核」面板查看、核准或拒絕帳號；後端由 Edge Function 驗證管理員身分並寫入稽核紀錄。
- 個人資料表的 RLS 政策已要求帳號為 `approved`；瀏覽器無法直接讀取帳號審核或管理員稽核表。
- 公告卡片改為「查看官方原始公告」，直接導向各校官方網址。
- 爬蟲輸出已改為公開最小預覽：只提交公告識別、學校、標題、官方網址、日期、分類與最多 180 字的摘要。
- 此功能合併到主分支後，第一次爬蟲執行會刪除公開的 `docs/data/details/` 歷史完整內文 sidecar；前端與問校務不再讀取這些公開完整內文檔。
- Staging 打包器改為自動處理所有 `?v=數字` 的資產版本，避免新版本沒有進入 staging 專用快取。

## 尚待驗證或執行

- **等待功能合併後的 GitHub Actions 爬蟲執行**：由機器人實際提交最小預覽 JSON，並刪除既有公開 `data/details/`。在此之前，既有靜態資料仍可能保有以前的完整明細，不能宣稱公開資料已完全清除。
- **帳號流程人工驗收**：以一個新帳號完成註冊、驗證、管理員核准、重新登入，確認待核准帳號無法使用個人功能而核准後可用。
- **CI 與 Preview**：每次推送會自動驗證；以最新 GitHub Actions 結果與 Vercel Preview 為準。
- Supabase Free 方案不能開啟 HaveIBeenPwned 外洩密碼保護；目前仍採至少 12 字元密碼、Email 驗證、登入錯誤不透露帳號是否存在、RLS 與管理員核准。

## 法律與資料界線

這是降低轉載、個資再散布與公開完整複製風險的工程措施，不是個別法律意見或保證。公開頁只提供必要索引與官方連結；校方公告仍以原發布頁為準。若要正式公開服務，仍須完成既有的來源權利、隱私／更正管道與臺灣法律專業審查證據。
